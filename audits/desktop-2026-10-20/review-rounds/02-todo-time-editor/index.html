To Do time editor

Keep the compact, in-context editor. Make it stay on screen, keep its actions reachable, and make hours entry and keyboard use more predictable.

What is already good

The editor keeps the board visible and groups the three relevant fields clearly: Stage, Hours and Note. The project name gives context. Save is the primary action, Cancel is explicit, and Delete is separated from the save group. Those are useful design choices to preserve.

The four recommended changes

TDP01 · High priority

Keep the editor on screen

Current: Save and Cancel sit below the viewport at both 1440 x 1000 and 1133 x 1000. The measured panel is 416px high; positioning reserves only 360px.

Proposed: Place the editor using its actual size. Open above the time block when there is more room, clamp it below the global header, and update its position when the workspace scrolls or resizes.

The editor can change side relative to its block. Preserve a small visual gap and the existing block context rather than introducing a full-screen dialog.

Observed defect · AC01 · Approved

TDP02 · High priority

Protect the header and action row

Current: The entire panel currently has one unbounded height. Enlarging Note or adding validation can push the actions further off screen. The framed Close also competes with the form fields.

Proposed: Keep project identity and a quiet DS Close control in the header. Keep Delete on the left and Cancel / Save on the right in a visible footer. Let only the fields scroll when space is constrained, retaining the existing field sizing, labels and Brisk styling.

A short desktop may need a little internal scrolling. This preserves readable controls and reachable actions without making the editor wider. Do not replace this specialised editor with the Columns settings popover.

Observed layout limitation plus design refinement · AC01 · Approved

TDP03 · Medium priority

Make valid hours obvious

Current: With Hours set to 0, the native field reports invalid, but Save stays enabled and there is no inline explanation. Source code would silently clamp and round the submitted number; that invalid save was not executed.

Proposed: Show a quiet hint: “0.25-24 hours, in 0.25-hour steps.” Allow temporary incomplete typing. Show a concise error after interaction when needed and disable Save until the value is valid. Never silently change the hours on Save.

Explicit validation asks the user to correct an invalid value. It is clearer than silently converting it. Keep the existing quarter-hour precision and 24-hour maximum; no new time policy.

Observed field state; save outcome supported by source · B15 · Approved

TDP04 · Medium priority

Make keyboard entry and exit predictable

Current: Enter opens the editor while focus remains on its time block. Escape from Hours leaves the editor open. Close and Cancel leave focus on the page body. The Stage list correctly consumes its own Escape.

Proposed: On keyboard opening, move focus to Stage. Let the Stage list handle Escape first; a subsequent Escape cancels the editor and returns focus to the original time block. Close and Cancel also return focus. Preserve non-modal access to the board and the existing explicit Save boundary.

Escape discards the local draft, matching Cancel. Keep that meaning explicit. Do not add autosave, a focus trap or the Media comment confirmation flow to this small editor.

Observed behaviour plus proposed interaction refinement · REF06 · Approved

Hours validation: visible value and Save disagree

Observed: Hours = 0, native validity false, Save enabled, no inline explanation. The source would clamp and round the number on Save. No invalid Save was executed.

Proposed copy: “0.25-24 hours, in 0.25-hour steps.” Use the existing DS hint/error treatment, with an understandable error only when needed. The existing limits stay the same.

Scope and trade-offs

Keep the existing explicit Save / Cancel boundary and separate Delete action. Escape will mean Cancel, so it discards an unsaved local draft. Keep the editor non-modal and avoid automatic saving or click-away dismissal.

Keyboard planning without dragging, the board's horizontal scrolling, stage-option vocabulary and broader To Do layout are separate decisions. This round does not add Day or status fields, change permissions or alter time policy.

No new Mobbin example is needed to resolve these measured layout and input issues. Brisk's scoped standards govern the recommendation; the exact editor arrangement still needs Tom's agreement.
